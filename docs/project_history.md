### History
Here's the history of Athena and how I've used it over the years. Some of this might be viewed as interesting while other bits help to explain the design decisions made. For fun I will link to the state of the project at various points in time. Additionally, Athena was written to solve several problems I had in my personal life, as a result this does touch upon that. Typically in documentation\projects I refrain from sharing personal matters, but in this document it seems appropriate (and one could argue is necessary to understand why this exists).

Athena started as a project originally to put all my applications in one place\allow me to run them easily. The original version was a shell script, entirely local, and required writting commands by hand. Effectively the shell script just scanned a few specific directories for scripts and listed them out. This worked for awhile, but it was pretty tedious to add programs. [Here](https://github.com/friedmicro/athena/commit/77c40e4f66feea861cc42f0dab75cc07d3d16b8c#diff-e016fc05eb90defa59ea573f99e46bec40f595fc3b18f45dbaf37b458d1cce43) is the code for the curious.

Eventually in 2024 I would relocate from Atlanta, GA to California. The months leading up to this also very much limited my time for things like games so I ended up adding in support for blacklisting games unless it was the weekend. Code is [here](https://github.com/friedmicro/athena/commit/a47e8a18f079faea22cc3776e6aab785e997ca6b) for the curious. This is in a lot of ways the first version of time limits\control in Athena.

The why I moved is not really relevant here, but I will say it was a very quick move and left me unemployed for a short period of time while I looked for work. Additionally...my partner and I are both very big into VR so we required dedicated spaces to actually play which due to latency meant that our computers would need to be in the same rooms as our playspaces\headsets. She got the bedroom and I got the living room. Small problem with this though...where were we actually supposed to use the machines\connect a mouse and keyboard? Also...with me being unemployed that severely limited out options to just buy hardware to fix it.

So remote software came into play...a few cheap dummy monitor plugs later and a few hours of tinkering with some software (fun note...did you know virtual displays are not really great in Linux...yeah I didn't either until this). I chose sunshine\moonlight to remotely control my system (low latency and support for Windows\Linux). My partner chose to use Parsec, but would later switch to the same solution. Athena still worked, but the limitations of the shell script gradually were starting to show. I wanted to add more features, I wanted reduce the time for setup of new games\manual configuration, and I wanted to be able to completely automate the machine\game startup.

At the time Athena as a local application so it was never designed to be used in this way; it couldn't start the machine in the next room, couldn't copy over any remote dependencies, still required every game definition file be written by hand, and had no extensibility. At this point I was employed and was also getting annoyed by the time limitations (limitations were by day...not a limit of time one could play). This ultimately prompted me to do a complete rewrite in a good glue language. For me this Python. [Here](https://github.com/friedmicro/athena/commit/09e50f49b7bec127eb157cd77a3d4cc6795c0ad4) is what the code looked like at this point after the rewrite.

In early-mid 2025 things would get put into motion for a surgical procedure which would result in limited mobility for a period of time (roughly a month). Tenative timeline was to be somewhere in 2026. At this point I realized...I need this to work...for myself because I'm not going to be able to just walk into the next room to turn on my machine (and configuring everything from a laptop by hand...did not seem viable).

In the background over the coming months in my free time I would add code to partly automate generating scripts to run the games and just plug them into the configuration file. For example, automating the configuration of steam games on remote machines and populating the athena configuration file to run a shell script to copy over a start script for the remote machine over ssh. Eventually doing some fairly hacky solution for Windows involving writing the start script to a Windows SMB share. From my perspective at the time, this code was all very experimental and a lot of it was just a solution to a problem I had. Some friends of mine would catch me streaming the game and also see Athena running a remote application, a few asked about it and a few of these became multi-hour engineering conversations. My dad would also see it while visiting just as a...yeah here's the server rack and here's how I connect to that machine. I realized...I had something here. I made a mental note to open source this once time allowed and to clean it up.

And then towards the end of 2025 I ended up getting that time...I would be informed my employment was coming to an end and shortly afterwards I would be informed my surgical date was early March. So about 4 months...not enough time to start a new job, not enough time for a contract, and not enough time to build a business venture. But it was enough time to bring it to a state where others can use it.

Plus hey, 4 months to build a project of your choice. Writing an application to remotely stream from systems and have a variety of applications being able to be run from one application is a pretty good one. :)
